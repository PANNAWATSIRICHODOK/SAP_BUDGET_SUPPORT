สรุปสถานะ Budget Add-on ล่าสุด

อ้างอิงจาก references/Store_And_Budget_New เป็นหลัก สรุปเฉพาะสิ่งที่ผู้ใช้ SAP ยังจะเจอ, สิ่งที่ vendor แก้แล้ว และสิ่งที่ควรแก้ต่อก่อน UAT รอบถัดไป.

2 จุดที่แก้แล้วจาก store ล่าสุด
3 ปัญหาที่ SAP ยังมีโอกาสติด
3 จุดที่ควรให้ vendor แก้ต่อ
3 flow หลักที่ต้อง retest
Expected ล่าสุด: ไม่รวม PR เข้า Budget แล้ว. Reserve ต้องเกิดจาก PO และ Actual ต้องเกิดจาก AP/CN/JE รวมถึงเอกสารรับจ่ายที่ยืนยันว่าอยู่ใน scope. เคส UAT ล่าสุด PO 50234 ยังไม่ขึ้น Reserve จึงยังถือว่า Budget Flow หลักไม่ผ่าน.

แก้แล้วใน Store ล่าสุด

1. Goods Return ถูกส่งเข้า Budget Control แล้ว

แก้แล้ว

จาก store ล่าสุด object 21 ถูกเพิ่มใน list ที่เรียก NDBS_BUDGET_CONTROL แล้ว และ Control มี branch เรียก NDBS_BUDGET_RETURN.

ผลใน SAP: Goods Return มีทางเข้า budget flow แล้ว แต่ควร retest ว่ายอด Actual/คืนยอดถูกต้องจริง.

SBO_SP_TransactionNotification.sql / NDBS_BUDGET_CONTROL.sql

IF :object_type In ('22','21','20','18','19','30') then

elseif ( :object_type = '21') then
  Call NDBS_BUDGET_RETURN (...);

2. Budget validation ถูกย้ายไปรวมใน Control

แก้แล้ว

Store ล่าสุดลบ Budget Noti block ออกจาก SBO_SP_TransactionNotification แล้วให้ NDBS_BUDGET_CONTROL ทำหน้าที่ตรวจฝ่าย/ปีงบ/งบตั้งต้นแทน.

ผลใน SAP: ไม่ควรมองว่า validation หายทันที แต่ต้อง retest ว่า PR/PO/AP ยัง block ช่องที่จำเป็นเหมือนเดิม.

NDBS_BUDGET_CONTROL.sql

IF :object_type ='1470000113' And (:transaction_type = 'A' OR :transaction_type = 'U') Then
  ... error_message := 'ISS รบกวนใส่ฝ่าย';
End If;

ใน SAP ยังจะติดปัญหาอะไรอยู่

1. Add PO แล้ว Monitor ยังไม่ขึ้น Reserve

ยังผิด

เคส UAT PO 50234 ยอด 10,000 ใช้ item ASS-004, group ASS1020203, department DP29-00, year 2026 แต่ Monitor ยังไม่แสดง Reserve.

ผลใน SAP: ผู้ใช้จะเห็นงบเหลือเท่าเดิม เช่น 132,700.00 ทั้งที่ Add PO แล้ว.

NDBS_BUDGET_PO.sql

FROM POR1 T0
INNER JOIN "@NDBS_BGC_BGPL" T3 ON T3."U_AccountCode" = T2."AcctCode"
WHERE T0."LineTotal" <> 0
  AND IFNULL(I1."InvntItem",'N') <> 'Y'
  AND T0."DocEntry" = :datakey;

INSERT INTO "NDBS_BGC_OBDE" (..., "Amount", "BudgetType", ...)
VALUES (..., :BAmount, 'R', ...);

2. Incoming / Outgoing / GI / GR ยังไม่ชัดว่าเข้า Actual

ยังเสี่ยง

Store ล่าสุดส่งเข้า Budget Control แค่ 22,21,20,18,19,30. ถ้ายังต้องให้ 24,46,59,60 กระทบ Actual ตามคู่มือเดิม จุดนี้ยังไม่ครบ.

ผลใน SAP: Monitor อาจไม่สะท้อนยอดจาก Incoming, Outgoing, Goods Receipt หรือ Goods Issue.

SBO_SP_TransactionNotification.sql / NDBS_BUDGET_JE.sql

IF :object_type In ('22','21','20','18','19','30') then
  call NDBS_BUDGET_CONTROL (...);
end if;

-- แต่ NDBS_BUDGET_JE ยังมี TransType:
T0."TransType" IN ('30','46','24','59','60')

3. PO ไป AP ยังต้อง Retest error 1299

ยังไม่พิสูจน์

Store ล่าสุดมี branch ตรวจ CANCELED ใน AP แล้ว แต่ logic หลักของ AP เปลี่ยนน้อยมาก. เคสเดิม Copy PO ไป AP แล้วเจอ 1299 no data found จึงยังไม่ควรสรุปว่าหาย.

ผลใน SAP: หลัง PO Reserve ยังไม่ถูก ต้องยังไม่ใช้ AP test เป็นตัวตัดสินสุดท้าย.

NDBS_BUDGET_AP.sql

error := 0;
error_message := N'Ok';
if(:transaction_type IN ('A','C')) then
  Select "CANCELED" into IsCancelled From OPCH Where "DocEntry" = :datakey;

ควรให้ vendor แก้อะไรต่อ

1. แก้ PO Reserve ให้สร้าง movement และ update Monitor ได้จริง

ต้องแก้

ก่อนแก้ต้องเช็คว่า PO 50234 มี row ใน NDBS_BGC_OBDE หรือไม่. ถ้าไม่มี row ให้แก้ NDBS_BUDGET_PO; ถ้ามี row ให้แก้ refresh/Monitor.

SELECT *
FROM NDBS_BGC_OBDE
WHERE "ObjectType" = '22'
  AND "ObjectID" = '50234';

Expected: ต้องมี Reserve 10,000 ใน group ASS1020203 / department DP29-00 / year 2026.

2. ยืนยัน scope และ dispatch ของ 24/46/59/60

ต้องยืนยัน

ถ้า Incoming, Outgoing, GI, GR ต้องขึ้น Monitor ตามคู่มือ ให้เพิ่ม object เหล่านี้เข้า TN/Control หรือให้ vendor ยืนยันว่า scope ล่าสุดตัดออกแล้ว.

SBO_SP_TransactionNotification.sql / NDBS_BUDGET_CONTROL.sql

3. ใช้ targeted refresh หรือยืนยัน performance ของ full refresh

ควรแก้

Store ล่าสุดมี NDBS_UpdateTouchedBudgetAmount และ index file แล้ว แต่ flow หลักยังเรียก NDBS_UpdateAllBudgetAmount ทุก transaction.

call NDBS_UpdateAllBudgetAmount;
