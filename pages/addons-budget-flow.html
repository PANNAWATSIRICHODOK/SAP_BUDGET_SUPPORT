UAT_JBF2 Budget Add-on Review Notes

ข้อเสนอให้ Vendor ตรวจสอบ

ข้อสังเกต Budget Add-on ก่อน port ไป SBO_*

เอกสารนี้เป็นข้อสังเกตจาก code/export ที่ได้รับ ไม่ใช่คำสั่งแก้. Vendor ต้องตรวจสอบ logic จริงและทดสอบก่อนปรับ code.

ใช้เทียบกับคู่มือ: Reserved = PR + PO, Actual = AP + CN + JE + OUTGOING + GI + GR.

P0

ควรตรวจสอบ CALL list กับ dispatch

ข้อสังเกต: TransactionNotification ส่ง 22,18,19,30,24,46,59,60 แต่ NDBS_BUDGET_CONTROL รับเฉพาะ 22,20,18,21,19,30.

ความเสี่ยง: 20/21 อาจไม่ถูกเรียก แม้มี procedure. 24/46/59/60 อาจเข้า control แล้วไม่มี branch รับ ทำให้ movement บางรายการไม่เกิด.

ข้อเสนอ: ให้ vendor ยืนยัน list ทั้งสองฝั่ง. หาก logic ควรผ่าน control ให้เพิ่ม 20,21,1470000113 ใน TransactionNotification และเพิ่ม route สำหรับ 24/46/59/60 ใน NDBS_BUDGET_CONTROL. หากจัดการที่ layer อื่นอยู่แล้ว ขอ test evidence ประกอบ.

File: SBO_SP_TRANSACTIONNOTIFICATION

IF :object_type In ('22','18','19','30','24','46','59','60') then
  call NDBS_BUDGET_CONTROL (...);
end if;

File: NDBS_BUDGET_CONTROL

--if ( :object_type = '1470000113') then
--  Call NDBS_BUDGET_PR (...);
if ( :object_type = '22') then
  Call NDBS_BUDGET_PO (...);
elseif ( :object_type = '20') then
  Call NDBS_BUDGET_GRPO (...);
elseif ( :object_type = '18') then
  Call NDBS_BUDGET_AP (...);
elseif ( :object_type = '21') then
  Call NDBS_BUDGET_RETURN (...);
elseif ( :object_type = '19') then
  Call NDBS_BUDGET_APCN (...);
elseif ( :object_type = '30') then
  Call NDBS_BUDGET_JE (...);
end if;

Test ยืนยัน: สร้าง PR, PO, GRPO, Goods Return, AP, APCN, JE, OUTGOING, GI, GR แล้วตรวจ NDBS_BGC_OBDE/OBPE ว่า movement เกิดครบ.

ควรตรวจสอบ PR reserve

ข้อสังเกต: คู่มือให้ PR เป็น Reserved แต่ call NDBS_BUDGET_PR ถูก comment, TransactionNotification ไม่ส่ง 1470000113, และ deploy package ชุดนี้ไม่มีไฟล์ NDBS_BUDGET_PR.

ความเสี่ยง: ยอด available อาจสูงเกินจริง และอาจจองงบเกินก่อนถึง PO.

ข้อเสนอ: ให้ vendor ยืนยันว่า PR reserve ทำที่ layer ใด. หากต้องทำใน Budget Control ให้เพิ่ม 1470000113 ใน CALL list และเปิด dispatch ไป NDBS_BUDGET_PR.

File: NDBS_BUDGET_CONTROL

--if ( :object_type = '1470000113') then
--  Call NDBS_BUDGET_PR (...);
if ( :object_type = '22') then
  Call NDBS_BUDGET_PO (...);

Test ยืนยัน: สร้าง PR non-inventory ที่มี budget year และ department/project แล้วตรวจว่า Reserved เพิ่มทันที. จากนั้นทำ PO จาก PR แล้วตรวจว่าไม่ reserve ซ้ำ.

P0

AP CopyTo เจอ no data found จาก datakey

ข้อสังเกต: UAT test แบบ PO CopyTo AP error ที่ NDBS_BUDGET_AP line 148 เพราะ procedure เอา :datakey ไปหา OPCH."DocEntry" แล้วไม่เจอ record.

ความเสี่ยง: SAP frontend จะ post A/P Invoice ไม่ผ่านทันที แม้ข้อมูลหน้าเอกสารถูกต้อง เพราะ backend budget procedure throw error กลับมา.

ข้อเสนอ: ให้ vendor ยืนยันค่า key ที่ส่งเข้า budget flow. สำหรับ AP ควรใช้ DocEntry จาก list_of_cols_val_tab_del หรือทำให้ datakey เป็นค่าเดียวกันจริงก่อนเรียก NDBS_BUDGET_AP.

File: SBO_SP_TRANSACTIONNOTIFICATION

call NDBS_BUDGET_CONTROL (
  :object_type,
  :transaction_type,
  :datakey,
  :list_of_key_cols_tab_del,
  :list_of_cols_val_tab_del,
  :error,
  :error_message
);

File: NDBS_BUDGET_AP

Select "CANCELED" into IsCancelled
From OPCH
Where "DocEntry" = :datakey;

Test ยืนยัน: ทำ PO CopyTo AP แล้วตรวจค่า datakey กับ list_of_cols_val_tab_del ใน TransactionNotification ว่าตรงกับ OPCH.DocEntry หรือไม่.

P1

ควรตรวจสอบ route ของ OUTGOING / GI / GR

ข้อสังเกต: 24/46/59/60 อยู่ใน CALL list และ NDBS_BUDGET_JE อ่าน TransType เหล่านี้ แต่ control call NDBS_BUDGET_JE เฉพาะ object_type = '30'.

ความเสี่ยง: Actual ของ OUTGOING/GI/GR อาจไม่เข้า budget ledger.

ข้อเสนอ: ให้ vendor ยืนยัน engine ที่ใช้กับ object เหล่านี้. หากใช้ NDBS_BUDGET_JE ให้พิจารณาเพิ่ม branch object_type IN ('24','46','59','60'). หากไม่ใช่ ให้ยืนยัน procedure/dispatch ที่ถูกต้อง.

File: NDBS_BUDGET_JE

Where (T0."Debit"-T0."Credit") <> 0
  AND T0."TransType" IN( '30','46','24','59','60')
  AND T0."TransId" = :datakey;

File: NDBS_BUDGET_CONTROL

elseif ( :object_type = '30') then
  Call NDBS_BUDGET_JE (...);
end if;

Test ยืนยัน: Post OUTGOING, GI, GR ที่มี budget-controlled account แล้วตรวจ Actual movement และยอดคงเหลือ.

P1

ควรตรวจสอบ APCN cancel condition

ข้อสังเกต: IF BCount >= 0 เป็นจริงเสมอ ทั้ง department และ project.

ความเสี่ยง: ระบบอาจ reverse จาก row ที่ไม่มีจริง เสี่ยง null, reverse ผิดงบ, หรือสร้าง movement ผิดตอน cancel A/P Credit Memo.

ข้อเสนอ: ให้ vendor ยืนยันเงื่อนไขนี้. หากต้องมี row ก่อน reverse ให้พิจารณาเปลี่ยนเป็น IF BCount > 0 then และกำหนด else path เมื่อไม่มี movement.

File: NDBS_BUDGET_APCN

Select Count(*) into BCount
From "NDBS_BGC_OBDE"
Where "PrimaryObjectType" = :BaseType
  AND "PrimaryObjectID" = :BaseKey
  AND "PrimaryObjectLine" = :BaseLine;
IF BCount >= 0 then
  Select TOP 1 "BudgetYear","BudgetGroup","Department"
  into OldYear,OldGroup,OldDept
  From "NDBS_BGC_OBDE";
end if;

Test ยืนยัน: Cancel APCN ทั้งแบบมี base document และไม่มี base document แยก department/project แล้วตรวจว่า reversal ไม่ผิดแถว.

P1

ควรตรวจสอบ AP account mapping

ข้อสังเกต: branch ใกล้กันใช้ U_FormatCode = FormatCode แต่จุดหนึ่งใช้ U_FormatCode = AcctCode.

ความเสี่ยง: A/P Invoice อาจลง budget group ผิด หรือหา group ไม่เจอ.

ข้อเสนอ: ให้ vendor ยืนยัน mapping key กลาง. หาก branch นี้ใช้ U_FormatCode ให้พิจารณาเปลี่ยน T4."AcctCode" เป็น T4."FormatCode". หากใช้ account code ให้ใช้ pattern U_AccountCode = AcctCode ทั้งไฟล์.

File: NDBS_BUDGET_AP

Inner Join OACT T4 ON T3."AcctCode" = T4."AcctCode"
Inner Join "@NDBS_BGC_BGPL" T5
  ON T5."U_FormatCode" = T4."FormatCode"

File: NDBS_BUDGET_AP

Inner Join OACT T4 ON T3."AcctCode" = T4."AcctCode"
Inner Join "@NDBS_BGC_BGPL" T5
  ON T5."U_FormatCode" = T4."AcctCode"

Test ยืนยัน: ทำ A/P Invoice จาก PO ที่ AcctCode และ FormatCode ต่างกัน แล้วตรวจว่า budget group ใน ledger ตรงกับ setup.

P2

Full refresh หลัง transaction ยังเป็นความเสี่ยงด้าน performance

ข้อสังเกต: NDBS_UpdateAllBudgetAmount ถูกแก้เป็น set-based แล้ว แต่ยังถูกเรียกแบบ full refresh ทุก transaction.

ความเสี่ยง: ไม่ใช่ bug เดิมแล้ว แต่ยังควรทดสอบกับข้อมูลเยอะและหลาย user เพราะ transaction เล็กก็ยัง recalc ทั้งระบบ.

ข้อเสนอ: ให้ vendor ประเมิน performance จริง. หากกระทบการใช้งาน ให้พิจารณา targeted recalculation เฉพาะ budget key ที่เอกสารกระทบ หรือใช้ background job ที่จำกัด scope ได้.

File: NDBS_BUDGET_CONTROL

if (error = 0) then
  DELETE FROM NDBS_BGC_OBPE WHERE "Amount"=0;
  DELETE FROM NDBS_BGC_OBDE WHERE "Amount"=0;
  call NDBS_UpdateAllBudgetAmount;
end if;

Test ยืนยัน: Post PO/AP/JE พร้อมกันหลาย user แล้วตรวจเวลา, lock, และยอดงบของ key ที่กระทบ.
