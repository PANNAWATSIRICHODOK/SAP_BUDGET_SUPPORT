UAT_JBF2 Budget Add-on Review Notes

ข้อเสนอให้ Vendor ตรวจสอบ

ข้อสังเกต Budget Add-on ก่อน port ไป SBO_*

เอกสารนี้เป็นข้อสังเกตจาก code/export ที่ได้รับ ไม่ใช่คำสั่งแก้. Vendor ต้องตรวจสอบ logic จริงและทดสอบก่อนปรับ code.

ใช้เทียบกับคู่มือ: Reserved = PR + PO, Actual = AP + CN + JE + OUTGOING + GI + GR.

P0

ควรตรวจสอบ CALL list กับ dispatch

ข้อสังเกต: TransactionNotification ส่ง 22,18,19,30,24,46,59,60 แต่ NDBS_BUDGET_CONTROL รับเฉพาะ 22,20,18,21,19,30.

ความเสี่ยง: 20/21 อาจไม่ถูกเรียก แม้มี procedure. 24/46/59/60 อาจเข้า control แล้วไม่มี branch รับ ทำให้ movement บางรายการไม่เกิด.

ข้อเสนอ: ให้ vendor ยืนยัน list ทั้งสองฝั่ง. หาก logic ควรผ่าน control ให้เพิ่ม 20,21,1470000113 ใน TransactionNotification และเพิ่ม route สำหรับ 24/46/59/60 ใน NDBS_BUDGET_CONTROL. หากจัดการที่ layer อื่นอยู่แล้ว ขอ test evidence ประกอบ.

IF :object_type In ('22','18','19','30','24','46','59','60') then
  call NDBS_BUDGET_CONTROL (...);
end if;

ควรตรวจสอบ route ของ OUTGOING / GI / GR

ข้อสังเกต: 24/46/59/60 อยู่ใน CALL list และ NDBS_BUDGET_JE อ่าน TransType เหล่านี้ แต่ control call NDBS_BUDGET_JE เฉพาะ object_type = '30'.

P1

ควรตรวจสอบ APCN cancel condition

ข้อสังเกต: IF BCount >= 0 เป็นจริงเสมอ ทั้ง department และ project.

ความเสี่ยง: ระบบอาจ reverse จาก row ที่ไม่มีจริง เสี่ยง null, reverse ผิดงบ, หรือสร้าง movement ผิดตอน cancel A/P Credit Memo.

ข้อเสนอ: ให้ vendor ยืนยันเงื่อนไขนี้. หากต้องมี row ก่อน reverse ให้พิจารณาเปลี่ยนเป็น IF BCount > 0 then และกำหนด else path เมื่อไม่มี movement.

Procedure: NDBS_BUDGET_APCN บรรทัด 123-133 และ 143-151

Select Count(*) into BCount
From "NDBS_BGC_OBDE"
Where "PrimaryObjectType" = :BaseType
  AND "PrimaryObjectID" = :BaseKey
  AND "PrimaryObjectLine" = :BaseLine;
IF BCount >= 0 then
  Select TOP 1 "BudgetYear","BudgetGroup","Department"
  into OldYear,OldGroup,OldDept
  From "NDBS_BGC_OBDE";
end if;

Test ยืนยัน: Cancel APCN ทั้งแบบมี base document และไม่มี base document แยก department/project แล้วตรวจว่า reversal ไม่ผิดแถว.

P1

ควรตรวจสอบ AP account mapping

ข้อสังเกต: branch ใกล้กันใช้ U_FormatCode = FormatCode แต่จุดหนึ่งใช้ U_FormatCode = AcctCode.

ความเสี่ยง: A/P Invoice อาจลง budget group ผิด หรือหา group ไม่เจอ.

ข้อเสนอ: ให้ vendor ยืนยัน mapping key กลาง. หาก branch นี้ใช้ U_FormatCode ให้พิจารณาเปลี่ยน T4."AcctCode" เป็น T4."FormatCode". หากใช้ account code ให้ใช้ pattern U_AccountCode = AcctCode ทั้งไฟล์.

Inner Join OACT T4 ON T3."AcctCode" = T4."AcctCode"

  ON T5."U_FormatCode" = T4."FormatCode"

P2

ควรประเมิน Full refresh หลัง transaction

ข้อสังเกต: เมื่อ error = 0 ระบบลบ zero movement แล้วเรียก NDBS_UpdateAllBudgetAmount ทุกครั้ง.

ความเสี่ยง: transaction เล็กก็ recalc ทั้งระบบ อาจช้าและ lock เมื่อข้อมูลเยอะหรือมีหลาย user.

ข้อเสนอ: ให้ vendor ประเมิน performance จริง. หากกระทบการใช้งาน ให้พิจารณา targeted recalculation เฉพาะ budget key ที่เอกสารกระทบ หรือใช้ background job ที่จำกัด scope ได้.

Procedure: NDBS_BUDGET_CONTROL บรรทัด 579-583

if (error = 0) then
  DELETE FROM NDBS_BGC_OBPE WHERE "Amount"=0;
  DELETE FROM NDBS_BGC_OBDE WHERE "Amount"=0;
  call NDBS_UpdateAllBudgetAmount;
end if;

Test ยืนยัน: Post PO/AP/JE พร้อมกันหลาย user แล้วตรวจเวลา, lock, และยอดงบของ key ที่กระทบ.
